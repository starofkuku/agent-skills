# Session Handoff

## 核心原则

- 当前会话的目标、决策和进度是主要交接内容。
- 当前相关文件和可观察结果用于验证事实。
- Git 状态仅是可选辅助信息，不能成为生成或恢复交接的前提。
- 原始会话记录只用于按需查询缺失的精确信息。

将调用 Skill 时的当前工作目录视为工作区根目录，不要自动替换为 Git 根目录。交接文件始终是 `<工作区根目录>/HANDOFF.local.md`。

## 选择模式

先读取 `HANDOFF.local.md`（如果存在），再选择模式：

- **准备交接**：文件不存在，或当前对话包含比文件更新、更完整的任务上下文。
- **恢复任务**：文件存在，当前是缺少任务历史的新会话，用户只调用了本 Skill 或要求继续交接任务。

不确定时比较文件记录的生成时间、工作区路径、相关文件状态和当前对话。不要在读取旧文件前覆盖它。

## 准备交接

1. 读取适用于当前工作区和相关项目的 `AGENTS.md`、`CONTRIBUTING.md` 及项目文档。把 `AGENTS.md` 视为长期规则，不向其中写入临时任务状态。
2. 从当前对话提取目标、范围、已完成工作、关键决策、失败路径和未完成事项。读取对话中提到的重要文件、模块和符号，以当前文件内容验证事实；不要递归扫描整个聚合工作区。
3. 如果任务涉及 Git，只检查实际参与当前任务的仓库。多个仓库分别使用 `git -C <repo> status --short --branch`、`git -C <repo> diff` 和最近提交进行辅助核验。不要枚举或加载所有无关仓库；没有 Git 或 Git 检查失败时仍继续交接，并记录限制。
4. 在工作区根目录创建或完整刷新 `HANDOFF.local.md`。除该文件和适用的 Git 本地 exclude 外，不修改代码、配置或其他任务文件，也不提交任何内容。
5. 如果交接文件位于某个 Git 工作树内，将它相对于该仓库根目录的精确路径加入 `git rev-parse --git-path info/exclude` 返回的文件，避免重复。若交接文件位于非 Git 聚合目录，不修改任何子仓库的 exclude，也不修改 `.gitignore`。
6. 保持文档紧凑、可执行，包含以下章节：

   ```markdown
   # Session Handoff
   ## Snapshot
   ## Goal And Scope
   ## Verified Facts
   ## Completed Work
   ## Decisions And Constraints
   ## Relevant Paths And Symbols
   ## Local Changes And Ownership
   ## Validation Results
   ## Known Issues And Failed Attempts
   ## Next Steps
   ## Environment
   ## Session Locator
   ## Uncertainties
   ```

7. 在 `Snapshot` 中记录生成时间、工作区根目录和任务摘要；仅在相关时记录参与任务的仓库、分支和 HEAD。在 `Local Changes And Ownership` 中说明当前任务产生的文件变化及禁止误删的用户改动，不要求这些变化必须由 Git 跟踪。
8. 记录实际运行过的命令及准确结果；未运行的测试写明“未运行”，不能写成通过。环境变量只记录名称和用途，禁止记录 token、密码、密钥或其他秘密值。
9. 明确区分已验证事实与推测。路径和符号尽量精确；下一步按优先级写成新会话可直接执行的动作。

## 会话定位信息

如果运行时已经提供当前 Session ID，或能从 `/status` 的已知结果获得它，则记录。只有在已有可靠信息、且无需扫描或读取全部历史记录时，才记录 transcript/JSONL 路径。无法确认时写 `Unavailable`，不要猜测内部目录结构，也不要为填写该字段加载完整 JSONL。

`HANDOFF.local.md` 必须能让新会话在通常情况下直接继续工作，不能依赖 Git 或旧日志才能理解主要任务。

## 完成交接

写完后重新读取交接文件，并用相关文件和可观察结果核对目标、改动、验证状态和下一步；Git 仅在相关时参与核对。报告文件路径与摘要，然后给出：

```text
/new <基于任务生成的简短名称>
$session-handoff
```

先完成交接再新建会话。不要建议使用 `/fork` 作为干净交接，因为它会复制当前聊天；不要依赖 Memories 代替即时交接文档。

## 恢复任务

1. 完整读取工作区内所有适用的 `AGENTS.md` 和 `HANDOFF.local.md`。
2. 读取交接中列出的相关文件、模块和当前可观察结果。仅对参与任务的 Git 仓库按需检查状态、diff 和最近提交；当前目录不是 Git 仓库或存在多个子仓库都不是错误。
3. 对比交接与当前工作区事实并标出过期或冲突信息。先简要说明当前目标、已完成状态、本地改动归属和最高优先级下一步。
4. 仅当交接缺少一个阻碍执行的精确信息时，才根据 Session ID 或可靠 transcript 路径查询旧记录。使用精确关键词、文件名、符号名或错误文本做有界搜索；不要一次性读取完整 JSONL。
5. 如果交接文件不存在、读取失败、存在阻碍继续工作的事实冲突或不足以确定任务，不要猜测，也不要删除文件。报告缺失内容并请求最小必要信息，以便重试恢复。
6. 只有在完整读取交接、核验相关工作区事实并确认当前会话已获得足够上下文后，才删除工作区根目录的 `HANDOFF.local.md`。如果曾添加 Git exclude 规则则永久保留，供下次交接复用。
7. 删除成功后直接继续最高优先级的未完成任务，不要求用户复述任务。删除失败时明确报告，不要声称交接已消费。

之后再次调用 `$session-handoff` 时，根据当前会话和工作区的最新事实创建全新的交接文件。
