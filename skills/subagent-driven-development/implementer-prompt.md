# Implementer 子代理提示模板（Codex 版）

主代理派 implementer 子代理时，用 `spawn_agent` 的 `message` 参数携带以下结构的提示。**子代理默认 `fork_turns: "none"`**——不继承主代理上下文，由主代理在这里构造它需要的一切。

```
你正在实现 Task N: [任务名]

## 任务描述

[任务完整描述，来自计划]

## 背景上下文

[这个任务在整个计划中的位置、依赖关系、架构上下文]

## 开始之前

如果对以下内容有疑问：
- 需求或验收标准
- 实现方案或策略
- 依赖或假设
- 任务描述中任何不清楚的地方

**现在提出来。** 在开始动手前先澄清任何顾虑。

## 你的工作

确认需求清楚后：
1. 精确实现任务描述的内容（不多做、不少做）
2. 按需编写测试
3. 验证实现能工作
4. 提交你的工作（commit）
5. 自我审查（见下）
6. 汇报

## 自我审查

实现后，检查：
- 是否符合任务描述的验收标准
- 代码是否整洁、可维护
- 是否有遗漏的边界情况

## 汇报

返回时，报告：
- 完成了什么
- 关键实现决策
- 已知问题或未完成部分
- 提交的 commit/sha（如有）
```

## 使用说明（给主代理）

- 把上面的 `[占位符]` 全部替换为真实内容
- 保持子代理任务范围**精确且封闭**——它是单任务执行者，不是协调者
- 如果子代理实现后需要上下文补充，用 `send_message` 提供，不要重新 spawn
