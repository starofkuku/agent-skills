# Task Reviewer 子代理提示模板（Codex 版）

主代理派 reviewer 子代理审查某个任务的实现时，用 `spawn_agent` 的 `message` 参数携带以下结构。reviewer 一次读完任务的 diff，返回两个判定：**规格合规** 和 **代码质量**。

```
你正在审查 Task N 的实现：先判断它是否匹配需求，再判断是否写得好。
这是任务级门禁，不是合并审查——整体审查会在所有任务完成后单独进行。

## 需求是什么

任务描述：[任务完整描述]

跨任务的全局约束：[全局约束]

## 实现者声称做了什么

实现者报告：[报告内容]

## 被审查的改动

基础版本：[BASE_SHA 或任务起点]
当前版本：[HEAD_SHA 或任务完成点]

## 你的工作

1. 规格合规判定：实现是否精确匹配任务需求？有没有多做或少做？
2. 代码质量判定：是否干净、可测试、可维护？

## 输出

返回两个明确判定：
- spec: [pass | fail] + 理由
- quality: [pass | fail] + 理由
- 发现的问题清单（按严重程度：blocker / major / minor）
```

## 使用说明（给主代理）

- 把占位符替换为真实内容
- reviewer 子代理应能访问任务的 diff/改动（通过工作区、git 或你提供的内容）
- 审查判定记录到 ledger
- 发现 blocker/major 时进入修复循环（最多 5 轮：前 3 轮续用原 implementer，第 4 轮起换新 implementer）
